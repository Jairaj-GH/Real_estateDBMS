-- (a) Rented houses built after 2023 in Guwahati SELECT address, city, construction_year, current_status FROM Property WHERE city = 'Guwahati' AND construction_year > 2023 AND current_status = 'rented'; -- (d) Top Agent by total sales in 2023 SELECT a.name, SUM(s.final_price) AS total_sales_amount FROM Agent a JOIN Sale s ON a.agent_id = s.agent_id WHERE YEAR(s.sale_date) = 2023 GROUP BY a.agent_id, a.name ORDER BY total_sales_amount DESC LIMIT 1; -- (c) Rentals on G.S Road — ≥2 BHK, under ₹15k/mo SELECT p.address, p.locality, p.no_of_bedroom, r.monthly_rent FROM Property p JOIN Rent r ON p.property_id = r.property_id WHERE p.city = 'Guwahati' AND p.locality = 'G.S Road' AND p.no_of_bedroom >= 2 AND r.monthly_rent < 15000;

Database-First Philosophy

All models use managed=False — Django never owns schema migrations. The SQL schema is the single source of truth, preserving full control over FK constraints, STRICT_TRANS_TABLES mode, and index definitions.

CORS & Auth Layer

django-cors-headers gates cross-origin requests from the Vite dev server. JWT tokens via django-simplejwt are injected by a custom Axios interceptor into every API call, enabling stateless RBAC.

Monorepo Structure

Frontend (/frontend) and backend (/backend) coexist in a single repository. Vite's proxy config routes /api/* to Django during development, eliminating CORS friction locally.

Technical Specifications

Architecture
decisions

The critical architectural choices extracted from configuration files, schema constraints, and the forensic codebase audit — each decision deliberate, each tradeoff documented.

settings.py — Core Config
# Database — single-user MySQL, utf8mb4 DATABASES = { 'default': { 'ENGINE': 'django.db.backends.mysql', 'NAME': 'DBPROJECT', 'USER': 'root', 'OPTIONS': { 'charset': 'utf8mb4', 'init_command': "SET sql_mode='STRICT_TRANS_TABLES'" } } } # Auth — JWT + role-based permission classes REST_FRAMEWORK = { 'DEFAULT_AUTHENTICATION_CLASSES': [ 'rest_framework_simplejwt.authentication.JWTAuthentication' ], 'DEFAULT_PERMISSION_CLASSES': [ 'rest_framework.permissions.IsAuthenticated' ] } # CORS — allow Vite dev server origin CORS_ALLOWED_ORIGINS = [ 'http://localhost:5173', ] # Models — managed=False throughout # Django never auto-migrates schema # SQL schema.sql is ground truth
🔐
RBAC Permission Classes
Four roles — admin, office, agent, customer — enforced via custom DRF permission classes. Sensitive endpoints like /admin/sql/ are double-gated: IsAuthenticated + IsAdminRole.
JWT Auth RBAC
⚛️
ACID Transaction Wrapping
transaction.atomic() wraps the entire purchase flow: Sale INSERT → Owner upsert → Property status UPDATE → agent counter bump. Any failure triggers a full rollback, preventing orphaned Sale records.
Atomic Rollback Safe
🔒
8 MySQL Trigger Guards
Rent overlap prevention via SIGNAL SQLSTATE '45000'. AFTER INSERT triggers automate current_status transitions from 'available' → 'sold' / 'rented', eliminating manual status management.
Triggers ×8 Overlap Guard
🗄️
Composite Indices for Analytics
Performance indices on high-query columns: idx_property_city, idx_sale_date, plus FK indices. The N+1 query pattern in SalesReportView (60 agents = 60 SELECTs) is flagged for future GROUP BY optimisation.
Indexed MySQL InnoDB
⚠️
Raw SQL Console — Risk & Mitigation
AdminSQLView uses connection.cursor().execute(sql) for arbitrary query execution. Mitigated by IsAdminRole gate + frontend guards blocking DROP/DELETE. Verbose error disclosure (str(e)) flagged for production masking.
High Risk Admin Only

Prompt Engineering

Building Real Estate DBMS
from Scratch

The exact prompts used to bootstrap the database‑first architecture, Django REST layer, ACID workflows, and premium glassmorphic frontend — each one driving a critical component of the final system.

Phase 1 Database‑First Foundation
🐍
Django Backend Initialization & ORM Bypass managed=False

"Initialize a new Django project (REST Framework). We are using a 'Database-first' approach. Create the Django models.py representations matching the SQL schema, but explicitly set managed = False for all models. We want Django to only act as an API bridge, not the database manager. Ensure connection settings map to our existing MySQL database."

Phase 2 Core Workflows & Logic
🏠
Customer Marketplace API

"Build the Customer exploration endpoints in Django. Create an API view (/api/properties/) that queries the Property table for rows where current_status = 'available'. ... create a POST interaction point where a customer can submit an inquiry, generating a row in the Notification table assigned to the property's underlying Agent."

🤝
Agent Transaction & Deal APIs

"Create the Agent Intelligence Hub endpoints. First, build a GET endpoint to return all Notification inquiries where receiver_id matches the authenticated Agent. Secondly, build a ConfirmNotificationView execution endpoint that securely inserts a record into the Sale or Rent table, and subsequently forces an UPDATE to change the corresponding property's status to 'sold' or 'rented'."

📊
High-Performance Database Analytics

"Build an Analytics Engine API for the Office Administrator. Instead of pulling all data to Python, write complex aggregations and GROUP BY logic directly through MySQL inside the Django view (e.g., finding the top agent by SUM revenue, calculating average property turn-around time). Return only the compacted KPI numbers to save memory."

Phase 3 Premium Frontend Integration
⚛️
React SPA Initialization & Glassmorphic UI

"Initialize the frontend using React and Vite. Develop a globally accessible, highly premium 'Liquid Glass' UI (glassmorphic theme, deep purples, smooth modern typography, and hover micro-animations). Set up routing structure and create a foundational axios API service interceptor to securely attach JWT tokens to every outbound HTTP request."

🎯
Customer & Agent Interface Development

"Develop the primary React interfaces. First, build the /marketplace page showcasing real-time fetched property cards with an elegant UI and 'Buy/Rent' buttons that dispatch the correct API payloads. Next, build an Agent Dashboard fetching the agent's notifications, complete with actionable buttons to finalize the real estate deals that communicate back to our Django endpoints."
